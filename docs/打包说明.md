# 打包说明

将 Xunzhi PDF Editor 打包为两个桌面平台产物：

- **Windows 便携版**：解压即用,无需安装
- **macOS 安装包**：dmg 格式（Apple 芯片 arm64）

## Windows 便携版

### 构建方式

#### 一、本地构建

```bash
npm run package:win
```

产出目录:`release/win-unpacked/`。

> 注意:在 macOS 上可以生成产物**目录结构**(`dir` 目标不需 Wine),但 `.exe` 本身无法在 macOS 上运行验证。运行测试需 Windows 机器。

#### 二、GitHub Actions CI 构建(推荐)

CI 在 `windows-latest` 上原生构建,产出可靠。

**触发方式:**

- **打 tag 触发正式 Release:** `git tag v0.1.0 && git push origin v0.1.0`
  - 构建完成后自动把 `XunzhiPDFEditor-portable-win-x64.zip` 附加到 GitHub Release
- **手动触发:** GitHub 仓库 -> Actions -> Build Windows App -> Run workflow
  - 产物作为 artifact 下载(不创建 Release)

### 产物

| 产物 | 说明 |
|---|---|
| `release/win-unpacked/` | 便携版目录(本地构建) |
| `XunzhiPDFEditor-portable-win-x64.zip` | 便携版压缩包(CI 产物) |

**使用方式:** 解压 zip,双击 `Xunzhi PDF Editor.exe` 即可运行,无需安装。

## macOS 安装包(arm64)

### 构建方式

#### 一、本地构建(需在 macOS 上执行)

```bash
npm run package:mac
```

产出:`release/Xunzhi PDF Editor-0.5.0-arm64.dmg`(未签名)。

#### 二、GitHub Actions CI 构建(推荐)

CI 在 `macos-latest` 上原生构建(workflow: `Build macOS App`)。

**触发方式:**

- **打 tag 触发正式 Release:** 与 Windows 共用同一个 tag,推 `v*` tag 后两个 workflow 同时构建,产物附加到同一个 GitHub Release
- **手动触发:** GitHub 仓库 -> Actions -> Build macOS App -> Run workflow
  - 产物作为 artifact 下载(不创建 Release)

### 产物

| 产物 | 说明 |
|---|---|
| `release/Xunzhi PDF Editor-0.5.0-arm64.dmg` | macOS 安装包(Apple 芯片) |

**使用方式:** 双击打开 dmg,把「Xunzhi PDF Editor」拖入「应用程序」文件夹。

### 首次运行说明(未签名)

当前应用**未做代码签名**(需 Apple Developer 证书,约 $99/年)。从网上下载的未签名应用会被 Gatekeeper 拦截,首次打开方式:

1. 在「应用程序」中找到 Xunzhi PDF Editor
2. **右键**(或按住 Control 点击)应用图标 -> **打开** -> 再次点击「打开」

之后即可正常双击启动。若想解除拦截,可在终端执行:

```bash
xattr -cr "/Applications/Xunzhi PDF Editor.app"
```

> 说明:未签名应用无法通过 `spctl` 公证,「系统设置 -> 隐私与安全性」中可能不显示"仍要打开"选项,以上右键方式始终可用。

## 应用图标

图标由 `scripts/generate-icons.mjs` 从内嵌 SVG 生成,产出三个文件:

- `build/icon.ico` — Windows
- `build/icon.icns` — macOS(仅 macOS 上生成,依赖系统自带 `iconutil`)
- `build/icon.png` — 1024 源图

如需更换图标:

1. 修改 `scripts/generate-icons.mjs` 中的 SVG 或改为读取外部 PNG 源图。
2. 运行 `npm run icons`,重新生成 `build/icon.ico` 与 `build/icon.icns`。
3. 提交 `build/` 目录到仓库。

## 配置说明

打包配置在 `package.json` 的 `"build"` 字段:

- `asar: false` - 字体/worker 作为真实文件存在于磁盘,规避 asar 内 `fetch(file://)` 加载字体不可靠的问题。
- `win.target: "dir"` - 产出便携目录,非安装器。
- `win.arch: ["x64"]` - 64 位 Windows。
- `mac.target: dmg, arch: ["arm64"]` - macOS 安装包,仅 Apple 芯片。
- `mac.category` - `public.app-category.productivity`,macOS 分类信息。

## 后续升级:代码签名

当前未签名。如需消除 SmartScreen 提示,需购买 Windows 代码签名证书:

1. 从 DigiCert / SSL.com 等 CA 购买 **OV 代码签名证书**(约 $200-400/年)。
2. 将 `.pfx` 证书和密码配置为 GitHub Secrets(`WIN_CERT` / `WIN_CERT_PASSWORD`)。
3. 在 `package.json` 的 `win` 配置中加签名配置,CI 工作流中注入证书。

> 注:EV 证书 SmartScreen 信誉更好但私钥通常存于硬件 token,CI 自动签名较麻烦,不推荐起步使用。
